# 青猫差旅比价工具第二版需求冻结稿与分阶段执行计划

日期：2026-05-20

## 1. 需求冻结结论

第二版不再只是航班比价工具。

第二版目标是做成一个本地采集、离线交付的差旅价格证明工具：

1. 航班比价从 3 平台升级为 4 平台。
2. 新增酒店比价。
3. 离线网页包同时包含航班和酒店。
4. Excel 同时包含航班和酒店。
5. 仍然不做云端自动采集，不做账号密码自动登录。

第二版新增平台：

- 在途商旅：`https://www.z-trip.cn/v/vcommon/home`

第二版统一对比平台：

- 青猫差旅
- 携程商旅
- 阿里商旅
- 在途商旅

第二版交付物：

- 航班 + 酒店一体化离线网页包
- 航班 + 酒店一体化 Excel
- 四平台截图证据
- 后台失败留痕

第二版不做：

- 真实公网网址部署
- 云端采集四平台数据
- 上传登录态、账号、密码、cookie
- 酒店打车混合大而全扩展
- 酒店主页面以长截图作为主要交付物

## 2. CEO Review

### 2.1 业务价值

第一版已经证明航班比价闭环可跑通。

第二版真正增加的价值不是“多抓一个平台”和“多抓酒店”这么简单，而是把销售材料从单一航班证明升级为差旅采购证明。

客户采购差旅时，航班和酒店通常一起看。只给航班，销售故事不完整。加上酒店后，青猫差旅可以同时证明：

1. 同一航班，青猫和主流商旅平台价格可比。
2. 同一酒店、同一日期、同一房型早餐口径，青猫和主流商旅平台价格可比。
3. 数据不是人工挑选，而是系统按规则从候选池随机抽取。
4. 每条结果都有网页截图证据，能复核。

### 2.2 用户核心路径

第二版仍然只有两类使用者：

- 用户本人：管理采集端使用者，负责登录平台、连接窗口、触发采集、导出交付物。
- 销售：拿离线网页包和 Excel 给客户演示或会后发送。

用户本人操作路径：

1. 打开登录浏览器。
2. 人工登录青猫差旅、携程商旅、阿里商旅、在途商旅。
3. 连接当前登录窗口。
4. 点击开始完整真实采集。
5. 等待系统完成航班和酒店采集。
6. 导出一体化 Excel。
7. 导出一体化离线网页包。

销售使用路径：

1. 解压离线网页包。
2. 打开 `index.html`。
3. 在首页选择航班比价或酒店比价。
4. 酒店页点击集团 tab 查看不同集团。
5. 客户需要复核时，打开 Excel 或网页截图证据。

### 2.3 为什么酒店不再以长截图为主

酒店数据天然更复杂：

- 5 个酒店集团
- 每个集团 8 家酒店
- 每家酒店 4 个房型早餐口径
- 每个口径 4 平台价格

如果继续用长截图，页面会非常长，客户无法点击切换集团，也无法快速定位。第二版酒店主交付改为离线网页包。

长截图不再是主交付物。最多作为当前页面或当前集团的临时导出能力，后续是否保留另行决定。

## 3. 航班第二版规则

### 3.1 平台升级

第一版航班对比平台：

- 青猫差旅
- 携程商旅
- 阿里商旅

第二版航班对比平台：

- 青猫差旅
- 携程商旅
- 阿里商旅
- 在途商旅

### 3.2 航班采样规则

航班采样沿用第一版主规则：

- 国内机票 10 条固定航线
- 国际机票 10 条固定航线
- 以青猫差旅作为航班候选池
- 每条航线随机抽取 1 个经济舱航班
- 国内只采直飞
- 国际优先直飞，没有直飞时允许中转
- 中转必须记录中转城市和总时长
- 出行日期沿用第一版规则：未来 3 天后

第二版新增规则：

- 抽中的航班必须在 4 平台都能找到同一航班号、同一日期、同一舱位口径价格。
- 任一平台没有同航班、无价格、不可订或采集失败，该候选航班放弃。
- 系统继续从青猫候选池随机尝试下一个航班。
- 对外展示只保留 4 平台完整航班样本。
- 被放弃的候选航班写入后台失败留痕。

## 4. 酒店第二版规则

### 4.1 酒店集团

第二版酒店覆盖 5 个集团：

1. 首旅如家
2. 华住
3. 锦江
4. 东呈
5. 亚朵酒店

品牌口径：

- 首旅如家：如家酒店、莫泰、YUNIK、艾扉、驿居、璞隐、扉缦、和颐至尚、如家云系列
- 华住：汉庭、全季、桔子、星程、漫心、禧玥、美仑、海友、怡莱
- 锦江：锦江之星、锦江都城、维也纳、丽枫、希岸、喆啡、7天酒店、凯里亚德、潮漫
- 东呈：城市便捷、宜尚、柏曼、精途、怡程、璟程、城市精选、隐沫
- 亚朵酒店：亚朵酒店

### 4.2 酒店城市池

第二版酒店固定城市池：

1. 北京
2. 广州
3. 杭州
4. 上海
5. 深圳
6. 武汉
7. 佛山
8. 成都
9. 厦门

酒店随机抽样要求尽量城市分散。

规则：

- 每个集团抽 8 家酒店。
- 优先让 8 家分布在不同城市。
- 如果某集团在部分城市候选不足，允许同城市补位。
- 补位原因写入后台留痕，不在销售页强调。

### 4.3 酒店日期和价格口径

酒店日期规则：

- 默认明天入住。
- 住 1 晚。
- 管理端第二版不做日期选择器。
- 价格统一按 1 间夜展示。

例子：

- 当前日期：2026-05-20
- 入住日期：2026-05-21
- 离店日期：2026-05-22
- 间夜数：1

### 4.4 酒店候选池

第二版酒店仍以青猫差旅作为候选池。

流程：

1. 在青猫差旅按城市和集团品牌搜索酒店候选。
2. 按集团随机抽酒店。
3. 优先城市分散。
4. 拿青猫候选酒店去携程商旅、阿里商旅、在途商旅匹配同一家酒店。
5. 四平台都匹配成功后，再进入房型价格采集。

任一平台没有同一家酒店，该酒店放弃，继续换下一家。

### 4.5 酒店房型和早餐口径

每家酒店后台尝试采集 4 个口径：

1. 大床无早餐
2. 大床有早餐
3. 双床无早餐
4. 双床有早餐

默认展示口径：

- 不再固定为 `大床有早餐`。
- 每家酒店按当前 4 个口径完整度动态选择默认展示口径。
- 同完整度时优先级为：大床有早餐 > 大床无早餐 > 双床有早餐 > 双床无早餐。

有效样本规则：

- 至少 1 个口径四平台都有价格，酒店才进入销售主展示。
- 4 个口径都不完整时，只进入后台留痕和失败记录。
- 4 个口径都必须尽量采集并展示。
- 缺失口径显示“暂无”。
- 缺失原因写入 Excel 留痕。

### 4.6 酒店匹配规则

酒店匹配不能假设不同平台房型名字完全一致。

匹配规则：

1. 酒店名只负责搜索候选，不作为最终判定依据；同城市 + 同门牌号一致，且品牌或名称没有明显冲突，判定为同一家酒店。
2. 门牌号不一致，判定不是同一家酒店；缺少门牌号时，不自动入库，进入人工确认或放弃。
3. 强匹配同一入住日期、同一床型、同一早餐口径。
4. 房型只归一为大床、双床；房型等级词不区分，例如标准、高级、舒适、商务、亲子都不单独拆口径。
5. 如果价格行出现“到店随机分配床型 / 随机分配床型 / 房型待定 / 到店安排”等字样，不自动入库，跳过这一条，继续找下一个明确房型价格。
6. 早餐只归一为有早餐、无早餐；单早不再作为独立口径。
7. `含早餐 / 含早 / 1份早餐 / 单份早餐 / 单早 / 2份早餐 / 双份早餐 / 双早` 均归为有早餐。
8. `无早餐 / 无早` 归为无早餐。
9. Excel 必须保留各平台原始房型名和原始早餐文案，方便人工复核。
10. 销售页展示归一口径，例如“大床有早餐”。

如果系统无法确认是否为同一家酒店或同一口径，不能强行入库，要放弃该候选并记录原因。

## 5. 第二版展示规则

### 5.1 离线网页包

第二版离线网页包是主交付物。

首页结构：

- 数据更新时间
- 本次批次 ID
- 航班比价入口
- 酒店比价入口
- Excel 下载入口

航班页：

- 国内航班
- 国际航班
- 四平台价格对比
- 青猫差额
- 查看网页截图

酒店页：

- 集团 tab：首旅如家、华住、锦江、东呈、亚朵酒店
- 每个集团展示 8 家酒店
- 每家酒店一张对比模块
- 每家酒店推荐口径突出展示
- 其他 3 个口径同页展示，但字体更小、颜色更弱
- 不折叠
- 不放到次级小表格
- 缺失口径显示“暂无”
- 每家酒店保留网页截图入口

### 5.2 Excel

第二版 Excel 是一体化工作簿。

Excel 不内嵌网页截图图片。截图证据保存在离线网页包证据目录中，Excel 只保留截图索引、证据编号、相对路径和说明。

建议 sheet：

1. 总览页
2. 航班汇总页
3. 酒店汇总页
4. 酒店集团明细页
5. 航班网页截图索引页
6. 酒店网页截图索引页
7. 内部留痕页
8. 失败记录页

Excel 必须保留：

- 航班原始字段
- 酒店原始名称
- 酒店归一名称
- 各平台原始房型名
- 归一床型
- 归一早餐口径
- 各平台价格
- 青猫差额公式
- 平台截图路径或索引
- 缺失原因
- 候选放弃原因

Excel 面向客户的汇总页要清楚，不要只像数据库导出。

Excel 和离线网页包的美观程度必须作为独立验收点，在假数据一体化闭环之后、真实采集放量之前先确认。

## 6. Eng Review

### 6.1 关键工程判断

第二版最大风险不是页面，而是四平台酒店匹配。

航班有航班号。酒店没有一个天然统一 ID。不同平台的酒店名称、商圈描述、房型名称、早餐文案都可能不同。

因此第二版必须把“候选识别、归一匹配、失败留痕”作为核心模块，而不是只在页面上多加几列价格。

### 6.2 建议新增和调整模块

#### 模块 1：在途商旅平台适配器

职责：

- 打开在途商旅入口。
- 验证登录状态。
- 支持后台附着当前登录窗口。
- 支持航班搜索。
- 支持酒店搜索。
- 读取价格。
- 保存截图证据。
- 输出失败原因。

#### 模块 2：四平台航班采集升级

职责：

- 复用第一版青猫候选池逻辑。
- 在现有携程商旅、阿里商旅采集后增加在途商旅采集。
- 四平台均有同一航班才进入当前批次。
- 失败航班写入失败记录。

#### 模块 3：酒店候选池采集

职责：

- 基于青猫差旅搜索酒店候选。
- 支持集团品牌过滤。
- 支持固定城市池。
- 支持每集团随机抽 8 家。
- 支持城市分散优先。
- 输出候选酒店、城市、集团、品牌、青猫页面证据。

#### 模块 4：酒店四平台匹配

职责：

- 根据青猫候选酒店匹配携程商旅、阿里商旅、在途商旅。
- 判断是否为同一家酒店。
- 记录原始酒店名。
- 记录归一酒店名。
- 不确定时放弃，不强行匹配。

#### 模块 5：房型早餐归一

职责：

- 抽取各平台房型文本。
- 识别大床、双床。
- 识别有早餐、无早餐。
- 至少 1 个口径四平台完整。
- 其他口径尽量采集，允许缺失。
- 保留原始房型名和归一口径。

#### 模块 6：一体化交付物导出

职责：

- 生成航班 + 酒店离线网页包。
- 生成航班 + 酒店 Excel。
- 保持证据文件可打开。
- 保证离线包不依赖本机服务。
- 保证 Excel 可复核。

## 7. 分阶段执行计划

### 阶段 0：第二版计划确认

目标：

- 用户确认本需求冻结稿。
- 用户确认分阶段执行计划。
- 确认后才进入编码。

通过标准：

- 用户明确回复通过。
- 不再新增第二版核心范围。

### 阶段 1：在途商旅单平台验证

目标：

- 先证明在途商旅可接入。
- 不直接改完整采集流程。

验证内容：

1. 在途商旅登录入口是否可打开。
2. 人工登录后是否可通过后台附着复用。
3. 航班搜索是否可进入结果页。
4. 酒店搜索是否可进入结果页。
5. 是否能读取目标价格。
6. 是否能保存网页截图。
7. 登录过期或失败时是否能明确提示。

通过标准：

- 1 条航班样本可读取价格和截图。
- 1 家酒店样本可读取价格和截图。
- 失败时有明确原因，不静默失败。

### 阶段 2：一体化假数据和客户交付物设计验证

目标：

- 在真实采集放量前，先用假数据确认销售展示网页和 Excel 的美观程度。
- 这是面对客户的材料，不能等到最后顺手检查。

工作内容：

1. 用假数据生成航班 + 酒店一体化离线网页包。
2. 用假数据生成航班 + 酒店一体化 Excel。
3. 酒店页展示 5 个集团 tab。
4. 每家酒店展示 4 个口径。
5. 每家酒店推荐口径突出展示。
6. 其他 3 个口径弱展示但可读。
7. Excel 不内嵌图片，只保留截图索引和证据入口。

通过标准：

- 销售打开网页 10 秒内能讲清楚主结论。
- 客户打开 Excel 不需要解释也能复核。
- 页面和 Excel 通过用户确认。

### 阶段 3：航班接入在途商旅

目标：

- 将第一版航班三平台升级为四平台。

工作内容：

1. 新增在途商旅航班采集适配器。
2. 修改航班有效样本规则为四平台完整。
3. 更新管理端航班状态。
4. 更新航班离线网页展示。
5. 更新航班 Excel。
6. 更新失败留痕。

通过标准：

- 国内航班可跑四平台同航班比价。
- 国际航班可跑四平台同航班比价。
- 导出的航班页和 Excel 都显示在途商旅价格。
- 旧的三平台成功样本不能误当作第二版成功样本。

### 阶段 4：酒店青猫候选池验证

目标：

- 先验证青猫差旅酒店候选池能否按集团、城市、品牌读取。

工作内容：

1. 读取 9 个城市酒店候选。
2. 按 5 个集团品牌识别候选。
3. 每集团随机抽酒店。
4. 优先城市分散。
5. 保存青猫候选池截图。

通过标准：

- 每个集团能拿到候选酒店。
- 能解释为什么某城市或某品牌候选不足。
- 候选池数据结构稳定。

### 阶段 5A：5 个集团酒店口径占比探针（已完成）

目标：

- 先验证 4 个房型早餐口径在 5 个集团酒店里的出现比例，再确定默认展示规则。
- 本轮已抽样 48 家酒店，`大床有早餐` 出现 39/48，曾作为固定默认主口径；现改为逐酒店动态选择默认展示口径。
- 本阶段不做四平台同店匹配。

工作内容：

1. 每个集团随机抽样最多 10 家酒店。
2. 验证大床无早餐、大床有早餐、双床无早餐、双床有早餐是否出现。
3. 统计每个口径的出现数量、出现比例和耗时。
4. 记录每个集团是否明显缺某个口径。
5. 根据真实完整率提出默认展示口径优先级建议。

通过标准：
