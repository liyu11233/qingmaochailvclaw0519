## 重要发现

- 青猫候选池中并非每家酒店都有大床双早。
- 例如部分候选酒店点击 `含早餐 + 大床房` 后显示无符合条件房型。
- 青猫酒店详情页存在一个实际问题：原始房型列表里有大床双早，但点击 `含早餐 + 大床房` 后，页面可能反而清空房型列表。因此当前实现以原始房型列表解析为优先，筛选只作为兜底。
- 因此酒店主口径闭环不能固定取候选池第一家，必须逐家尝试，直到找到青猫自己有大床双早的酒店。
- 这一点会影响后续 40 家酒店放量：每个集团 8 家有效样本必须以“青猫主口径存在”为前置条件。
- 携程商旅酒店入口没有普通“搜索”按钮，需要在酒店 tab 中输入城市和酒店关键词，点击酒店建议后通过 `因公出行` 进入酒店列表，再进入同酒店详情页。
- 携程商旅可在账号只允许查看行程、不可预订的状态下读取酒店价格；当前阶段先按可见价格完成同口径比对，后续放量时仍需记录账号权限状态。
- 在途商旅搜索不能只点搜索按钮；需要先用酒店名关键词触发建议列表，再点击建议里的同酒店，否则主列表可能仍是默认推荐酒店。
- 青猫酒店关键词选择存在异步脆弱点；现在只以输入框 value 判断关键词是否选中，避免页面正文包含酒店名时误判为已选中。

## 2026-05-22 酒店匹配口径更新

本轮先统一酒店、房型、早餐判断规则，再进入后续代码调整。

已确认酒店命中逻辑：

- 酒店名只负责搜索候选。
- 地址负责定真假。
- 同城市 + 同门牌号一致，且品牌或名称没有明显冲突，判定同一家酒店。
- 门牌号不一致，判定不是同一家酒店。
- 缺少门牌号时，不自动入库，进入人工确认或放弃。
- 阿里商旅列表页缺少门牌号是正常现象，不能仅凭列表无门牌放弃；列表页只判断是否值得进入详情。
- 阿里搜索优先级为：酒店全名、去括号但保留核心地名、品牌 + 核心地名/商圈/景区、地址/路名/门牌号辅助、纯品牌兜底。
- 阿里详情页才做最终同店确认：读取详情地址并提取门牌号，同城市 + 门牌号兼容才算同店；同关键词最多尝试前 3 个详情候选。

已确认房型逻辑：

- 房型只分 `大床` / `双床`。
- 不区分商务、高级、精英、亲子等房型等级词。
- 如果价格行出现“到店随机分配床型 / 随机分配床型 / 房型待定 / 到店安排”等字样，不再一律跳过。
- 只要主房型名称明确写着 `大床` 或 `双床`，仍按有效房型入库。
- 只有主房型不明确、只能看到随机/待定床型时，才跳过该价格行，继续找下一个明确房型价格。

已确认早餐逻辑：

- 删除单早口径。
- 早餐只分 `有早餐` / `无早餐`。
- `含早餐 / 含早 / 1份早餐 / 单份早餐 / 单早 / 2份早餐 / 双份早餐 / 双早` 均归为有早餐。
- `无早餐 / 无早` 归为无早餐。

因此酒店口径从 6 个调整为 4 个：

1. 大床无早餐
2. 大床有早餐
3. 双床无早餐
4. 双床有早餐

主口径调整为：
